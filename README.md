# CooBee Recommendation Harness

Исследование архитектур LLM для рекомендаций подарков (НИР, 3 семестр).

**Цель проекта:** Проверить, может ли LLM (GigaChat) заменить или дополнить бизнес-правила в продукте CooBee, и доказать необходимость инженерной обвязки (Structured Harness).

## 📊 Ключевые результаты

В ходе Ablation Study (6 конфигураций) были получены следующие результаты на тестовом наборе из 32 запросов:

| Конфигурация | NDCG@5 | Описание |
| :--- | :--- | :--- |
| **B0: Business Rules (MVP)** | 0.6048 | Жесткие фильтры по бюджету и тегам (baseline продукта) |
| **B1: Single-shot LLM** | 0.4871 | «Голая» GigaChat без предфильтрации (хуже правил на 19.5%) |
| **H5: Structured Harness** | **0.7282** | Гибридное ранжирование (LLM + теги + рейтинг) — **+20.4% к B0** |
| **H6: Diversified (4+1)** | **0.7617** | Архитектура с гарантированным «сюрпризом» (+25.9% к B0) |

**Главный вывод:** Наивное подключение LLM ухудшает качество. Только Structured Harness позволяет превзойти бизнес-правила и гарантирует 0% галлюцинаций и нарушений бюджета.

## 📂 Структура проекта

- `catalog_research_v4.csv` — каталог 80 товаров (29 атрибутов).
- `golden_set.csv` — 32 тестовых запроса с ручной разметкой (grade 2/1/0).
- `experiment_protocol.md` — полный протокол эксперимента (гипотеза, метрики, ограничения).
- `ndcg_results_chart.png` — график Ablation Study.

**Скрипты:**
- `auto_save_results.py` — запуск конфигураций Harness (H1–H6).
- `rerun_b1_300.py` — прогон «голой» LLM (B1).
- `final_analysis.py` — расчет B0, Bootstrap CI и итоговой статистики.
- `deep_analysis.py` — детальный разбор результатов (доказательство, что B1 хуже).
- `stratified_analysis.py` — разбивка качества на «очевидные» и «неочевидные» запросы.
